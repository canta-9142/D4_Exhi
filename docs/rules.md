# ゲームのルール v2.0

## ノードとパケット

- プレイヤーノードは8個（A〜H）、ボットノードは3個（I〜K）。
- ノード同士は決められた経路で接続されている。
- パケットには、それぞれ目的地が設定されている。
- 各ノードには転送待ちのパケットが蓄積する。
- 運転中（次節）は、各プレイヤーノードに、1pkt/sのペースで、宛先が自分以外のプレイヤーノードに設定されたパケットが自動生成される。
- ボットノードを出発地点として新たに生成されることはない。

## 運転とラウンド

管理者がWebの管理画面で「運転開始」を押すと運転中になり、「運転停止」を押すまでゲームを回し続ける。サーバーの起動直後は停止中である。停止中はパケットの生成・転送・得点を行わず、プレイヤー筐体は休止中の表示になる。運転を開始するときと停止するときは、パケット・スコア・タイマーを初期化する。

運転中はネットワークが止まらない。パケットの生成と、ボットノードおよび自動転送中のプレイヤーノードの転送は、プレイヤーがいない筐体でも続く。プレイヤーが遊ぶ単位を「ラウンド」とし、筐体ごとに独立して行う。隣の筐体のラウンドと開始・終了をそろえない。同時に遊ぶ人がそろうのを待たず、ボタンを押したらすぐに始められるようにするためである。

### 筐体の段階

運転中の筐体は、次の5つの段階のどれかにある。停止中を加えると6つである。

| 段階 | 内容 | 次の段階 |
|---|---|---|
| 停止中 | パケットの生成・転送を行わない。休止中の表示 | 運転開始で待機 |
| 待機 | ボットとして自動転送（2pkt/s）する。得点は数えない。受付中の筐体には長押しの案内を出す | 受付中の筐体で両端のボタンを2秒長押しすると、モード選択 |
| モード選択 | 練習（TUTORIAL）か通常（NORMAL）を選ぶ。自動転送は続く | 左から2番目のボタンで練習、左から3番目のボタンで通常。20秒間選ばなければ待機 |
| 通常ラウンド | 3秒のカウントダウンの後に、90秒のゲーム時間。プレイヤーが手動で転送する | 90秒が終わると結果。打ち切りでは待機 |
| 練習ラウンド | 3秒のカウントダウンの後に、時間制限なしで練習する（「チュートリアル（練習）」） | 両端を2秒長押しするとモード選択。60秒間操作がなければ待機。打ち切りでは待機 |
| 結果 | 通常ラウンドの結果を30秒表示する。自動転送は続く | 30秒以内に両端を2秒長押しするとモード選択。しなければ待機 |

```text
停止中 ──(管理: 運転開始)──▶ 待機
                             │  受付中（手動）で両端を2秒長押し
                             ▼
               ┌──────── モード選択 ──(20秒)──▶ 待機
               │              │左から3番目           │左から2番目
               │              ▼                       ▼
               │   通常ラウンド（3秒＋90秒）   練習ラウンド（3秒＋無制限）
               │              │90秒                   │両端2秒 ─▶ モード選択
               │              ▼                       │60秒操作なし ─▶ 待機
               └─(両端2秒)── 結果（30秒）──(30秒)──▶ 待機

どの段階からも: 管理の「ボットに戻す」「自動」、MCU切断、FIFO上限 ─▶ 待機（打ち切り、記録なし）
運転中のどの段階からも: 管理の「運転停止」 ─▶ 停止中
```

| 時間 | 秒数 |
|---|---|
| モード選択の制限時間 | 20 |
| カウントダウン | 3 |
| 通常ラウンドのゲーム時間 | 90 |
| 結果の表示 | 30 |
| 練習の無操作の制限時間 | 60 |

両端のボタンを同時に2秒押し続ける操作を「長押し」と呼ぶ。押し始めのタイミングが一致する必要はない。長押しは、待機・結果・練習中に「モード選択へ進む」合図として使う。モード選択は内側の2つのボタンで行う。両端のボタンは長押しの合図に使っているため、選択には使わない。

通常ラウンドを選ぶと、そのノードの自動転送をカウントダウンの開始で止め、プレイヤーが手動で転送する。カウントダウン中もネットワーク全体は動いているので、そのノードのFIFOにはパケットが届く。転送の操作は、カウントダウンが終わってから受け付ける。カウントダウンは、プレイヤー筐体の画面に表示し、管理画面にも残り秒数を出す。

通常ラウンドのゲーム時間が終わると、そのラウンドの結果を確定して結果の段階へ移り、そのノードの自動転送を再開する。結果の段階では、そのラウンドの得点・上位%・ベストスコアを示す。結果を見た人がすぐにもう一度遊べるよう、30秒以内に長押しするとモード選択へ進める。

### 打ち切り

次の契機では、ラウンド・モード選択・結果を途中で打ち切り、その筐体を待機へ戻す。運転停止では全筐体を停止中へ戻す。

| 契機 | 内容 |
|---|---|
| 管理操作「ボットに戻す」 | 対象の筐体を待機へ戻す。受付は続ける（次の人をすぐ受け付けられる） |
| 管理操作「自動」 | 対象の筐体を待機へ戻し、ボット固定にする。以後、長押しを受け付けない |
| MCUの切断 | 対応するプレイヤーMCUが切断されたとき。自動操作に切り替わる |
| FIFOの上限 | 通常ラウンドのプレイヤーのFIFOが1000件に達したとき。MCUのキャッシュが1024件のため、放置された筐体などで超えないようにする |
| 練習の無操作 | 練習ラウンドで60秒間、転送の操作が1件も受理されなかったとき。離席した筐体の画面が待機に戻らない状態を防ぐ |
| 運転停止 | 管理操作。全筐体を停止中へ戻し、生成・転送を止める |

通常ラウンドの打ち切りは、結果を確定せず、結果画面も出さず、記録しない。打ち切りは運営の事情で起こり、ベストスコア・上位%の対象外になるだけなので、残す意味が薄い。モード選択の20秒と結果の30秒が過ぎて待機へ戻ることは打ち切りではない。

## チュートリアル（練習）

練習は、時間制限なしで、ヒントを見ながらひたすら練習するラウンドである。得点の対象にならず、ランキングや採点にも影響しない。

- 練習中の画面には、先頭のパケットの宛先にどのボットのボタンから近づけるかを示すヒントを出す。宛先が両隣のプレイヤーノードであれば、そのボタンを押せば直接届くため、ボットのヒントは出さない。
- 練習で操作するパケットは、練習のために作る仮想のパケットで、常に3件が手元にある。送ると直ちに補充される。宛先は自分以外のプレイヤーノードから無作為に選び、両隣宛ても含める。TTL・経路・パケットロスは持たない。時間無制限の練習なので、時間をかけて溜める必要がない。
- 練習で転送しても、ネットワーク上のパケット・LED・得点・記録には何も起きない。
- 練習の得点は数えない。記録せず、ベストスコア・上位%の対象外とする。
- 練習中も、実際のネットワークでは、そのノードは自動転送（2pkt/s）のまま中継を続ける。プレイヤーは他のプレイヤーのパケットの中継点でもあり、練習者が実際のFIFOを遅く捌くと、そこを通る他人のパケットが滞留して他人のスコアが下がるためである。練習者の操作は、他の人のスコアに影響しない。
- ボットの混雑は、練習中も実際の値を示す。満杯のボットへ転送するとパケットロスになる規則（「パケットロス」）を、練習中に知れるようにするためである。練習の転送自体はパケットロスにならない。

## スコア

- 通常ラウンド1回（ゲーム時間90秒）で得られたスコアを競う
- 自分が発信した・中継したパケットが目的地に到達した時点でスコアとして加算される。
  - 2ホップ以内: 発信した人に15点、中継した人に8点
  - 3ホップ以上: 発信した人に10点、中継した人に8点
- パケットが「パケットロス」となった場合、そのパケットによってスコアが加算されることはない。
- ゲーム時間が終了した時点で到着していないパケットは、スコアとして加算されない。
- 得点を数えるのは、通常ラウンドのカウントダウンが終わってからゲーム時間が終わるまでの間に、そのノードに入った点だけである。パケットがいつ生成されたかは問わない。ラウンドの開始前に生成されたパケットを中継して届いた場合も、ゲーム時間中に届けば加算する。ノードごとに開始と終了の時刻で区切るだけで済み、これまでの得点の規則を変えずに連続運転へ移せるためである。
- 待機・モード選択・結果・練習の間に入る点は数えない。

## 最終順位

ラウンドは筐体ごとに1人で行うため、順位を付けない。同時に遊ぶ人がそろわないので、ゲームの中での順位に意味がないためである。ラウンドの結果は、次の「上位%」と「ベストスコア」で示す。

旧来の一斉ゲーム（8人が同時に90秒遊ぶ）の記録には、当時の規則で付けた順位が残っている。同点は同順位とし、順位は「自分より最終スコアが高い対象者の人数＋1」であった。この順位は、現在の画面には表示せず、集計にも使わない。

## 上位%

通常ラウンドの結果を確定するときに、これまでの通常ラウンドの得点の中で自分が上位何%にあたるかを求める。順位を付けない代わりに、過去の記録を含めた位置を示す。

- 母集団は、ベストスコアの1時間ごと・通算と同じものとする。通常ラウンドを90秒最後まで行ったものの得点と、旧来の一斉ゲームでゲーム時間（90秒）を最後まで行ったゲームの、ランキング対象者の最終スコアである。今回のラウンドの得点も母集団に含める。
- 上位%は、100 × （母集団で自分より得点が高い件数 ＋ 1）÷ 母数 を切り上げた整数とし、1〜100に収める。同点は、自分より高い件数が同じなので同じ値になる。母数（母集団の件数）の大小にかかわらず付ける。例えば母数が200件で、自分より高い得点が19件なら10%となる。母数が少ないうちは値が粗く、母数が1件なら最高点でも100%であり、1%になるのは母数が100件以上のときである。
- 打ち切ったラウンドと練習には付けない。
- プレイヤー筐体には、上位50%以内（50%を含む）の人にだけ値を通知する。51%以上の人には値を伏せ、下位50%であることだけを通知する。管理画面には、1〜100の全員分を示す。
- 起動時に記録ファイルを使えなかったときは、プレイヤー筐体には通知しない。管理画面には、その起動中のラウンドだけを母集団として求めた値を示す。
- 上位%はラウンドの結果を確定するときに1回だけ求め、以後のモード変更、切断、再接続、基板交換では変更しない。結果の段階を出るときに消す。

## ベストスコア

通常ラウンドの結果はサーバーに記録し、管理画面に次の3種類のベストスコアを示す。記録はサーバーを再起動しても引き継ぐ。

| 種類 | 内容 |
|---|---|
| 直近のラウンド | 終わったラウンドの得点を、新しい順に並べたもの。ノード・得点・上位%・時刻を示す |
| 1時間ごと | 日本時間の正時で区切った時間帯（13:00〜13:59など）ごとの最高点 |
| 通算 | これまでの全体での最高点 |

- 対象は、通常ラウンドを90秒最後まで行ったものの得点と、旧来の一斉ゲームでゲーム時間（90秒）を最後まで行ったゲームの、ランキング対象者の最終スコアとする。ランキング対象外のプレイヤーの点と、打ち切ったラウンド、練習、ゲーム時間が現在と異なっていた旧来のゲームは含めない。
- 1時間ごとでは、ゲーム時間が終わった時刻の時間帯にそのラウンドを含める。
- 直近のラウンドは、結果を確定したラウンドを新しい順に並べる。直近の何件を示すかは管理画面の仕様に従う。
- 同点の場合、1時間ごと・通算では、先に終わったものを採る。旧来の一斉ゲームでは、そのゲームで同点の対象者を全員示す。
- プレイヤー筐体に示す「その回」のベストスコアは、そのラウンドの自分の得点とする。ラウンドは1人で行うため、その回に最高点を取った人は常に自分である。1時間ごと・通算は、そのラウンドの結果を加えた後のベストスコアである。

## パケットの転送

プレイヤーは、接続された隣接ノードから転送先を選択する。

転送対象は常に自分のノードで最も古いパケット（FIFO）。

プレイヤーはパケットを任意に選択したり、接続されていないノードに直接送信したりすることはできない。

## 自動操作

自動転送はどのノードであったとしても事前に計算された優先順位に従って行われる。状況による優先順位の変更もない。

### プレイヤーノード

プレイヤーノードの操作状態は、手動と自動の2つである。

| 操作状態 | 意味 |
|---|---|
| 手動 | 人の参加を受け付ける（受付）。受付中でも、ラウンドが始まるまでは、ボットとして自動転送する |
| 自動 | ボットに固定する。長押しを受け付けない。ラウンド中に自動へ切り替えるとラウンドを打ち切る |

プレイヤーが入っていない筐体は常にボットとして動かす。受付を続けたまま空いている筐体をボットにしておき、運営が壊れた筐体を止める操作（自動）とは区別する。

サーバーの起動直後は全員を自動とする。管理画面から、いつでも手動・自動を切り替えられる。手動にできるのは、対応するプレイヤーMCUが接続・識別済みのノードだけである。全員を一括して切り替える操作もある。

管理画面の「ボットに戻す」は、ラウンド・モード選択・結果を打ち切って待機へ戻す。手動（受付）のままなので、次の人をすぐ受け付けられる。「自動」は打ち切ったうえでボットに固定する。次の人を受け付けるには、手動へ戻す。

対応するプレイヤーMCUが切断された場合は、自動操作に切り替わる（ラウンドの途中なら打ち切る）。再接続しても自動操作を継続し、手動へは復帰しない。

自動転送は、待機・モード選択・結果の間と、練習中の実際のネットワークで行う。パケット生成のルールは変わらず、2pkt/sのペースでパケットの自動転送を行う。

得点方法は手動操作と同じであり、数えるのは通常ラウンド中だけである（「スコア」）。通常ラウンドは手動で行うので、自動操作のまま最後まで進むことはない。ラウンド中に自動操作へ切り替わった場合は打ち切り、結果を確定しない。

### ボットノード

ボットノードは常に自動操作モードで動作する。

ボットノードの自動転送は1pkt/s、保持できるパケット数は4件である。

## パケットロス

### 輻輳

転送先のボットノードのバッファが満杯の場合、転送したパケットは破棄され、パケットロスとなる。

### タイムアウト

このゲームのパケットのTTLは一律5であり、ノード間を転送されるたびに1減少する。TTLが0になった時点で目的地に到着していないパケットは、パケットロスとなる。

### ネットワークループ

すでに通ったことのあるノードにパケットが到着した場合、そのパケットは破棄され、パケットロスとなる。
