## シグナルタワー

シグナルタワーは、ボットノードの上に一周するように設置されたLEDテープで、各ボットノードのバッファの埋まり具合を示す。0~1件なら青、2件なら緑、3件なら黄色、4件なら赤に点灯する。

60LED/mのテープを使用する。

## パケット経路の点灯パターン

30LED/mのテープを使用する。

1フレームを10msとして1フレームごとに点灯位置を1つずつ移動させる。
尾の長さを10LEDとして、最高輝度255、最低輝度0でおおよそでよいので等比的に減衰させる。

点灯色はパケット目的地のノードに対応する色で点灯させる。

サーバーからの命令によっては点灯するLEDの位置が被ってしまう場合があるはずだが、この場合は両者を加算した値で点灯させる。加算した値が255を超える場合は255で飽和させる。

# サーバー↔LEDノード間通信インターフェース

## 基本仕様

- 通信経路: USB CDC
- データ形式: 改行区切り独自プロトコル。ただし識別要求`identify`はプレイヤーMCUと共通のJSON形式
- MCU: ESP32-C3, Arduino
- サーバー: 同

## メッセージ形式

メッセージ単位はLF区切り、命令・引数同士はスペース区切り。共通の識別要求`identify`のみ、次節のJSON形式で受信する。

```txt
OPERATION OPTIONS
```

## 接続・識別

サーバーは新しいシリアルセッションで接続先の種別が未確定でも、次の共通識別要求をLF終端で直ちに送信し、有効な識別応答を受信するまで1秒間隔で再送する。

```json
{"type":"identify","data":{}}
```

この要求のJSON形式・必須フィールドの扱いは[プレイヤー通信仕様のJSON形式](./player.md#json形式)に従う。LED制御MCUは設定済みかどうかによらず`identify`を受け付け、直ちに既存形式の`HELLO UID`をLF終端で返す。繰り返しの要求にも毎回応答する。

サーバーはJSON形式の`hello`をプレイヤーMCU、`HELLO UID`をLED制御MCUの識別応答として受け付け、有効な応答の形式から種別を確定して`identify`の再送を停止する。識別前の不正な入力では種別を確定せず、入力を破棄して識別要求を継続する。種別確定後は対応する通信仕様に従って設定・同期へ進む。

`CONFIG`・`LIGHT`・`BUFFER`・`CLEAR`は引き続きスペース区切りの形式を使用する。通常の設定時の命令順序は次節、ゲームReset時は「CONFIGの適用とゲームReset」に従う。不正な`CONFIG`以外の異常時処理は別途定義する。

## UIDの割当と基板交換

UIDとLED制御ノードIDは一対一に対応付け、サーバーが管理する。割当先は上記の担当リンク表にあるB1・B2・B3・P1・P3・P5・P7とする。プレイヤーMCUの割当とは別に管理し、機器種別をまたいで割り当てない。

初めて識別したUIDには、Preparing・Finishedで既存の対応を上書きせず、空いているLED制御ノードIDを自動で仮割当し、下記の通常設定手順を行う。「実機の確認表示」節の手順で実機の配置を確認し、管理者がWeb管理画面から本番の割当へ変更する。仮割当は通常の対応表を使用し、専用の確定操作は設けない。

管理画面からは空いているIDへの割当・移動・解除に加え、2台の割当を一括で交換する操作と、予備基板への付け替えを行える。変更はPreparing・Finishedでのみ受け付け、サーバー仕様の[割当・交換規則](./server.md#421-デバイスの割当交換)に従う。予備基板への付け替えでは旧UIDを未割当にし、新UIDへ同じ役割を引き継ぐ。新UIDに既存の仮割当があれば解除する。

自動仮割当・再接続・担当変更時の通常設定は、対象の確認表示の周期送信を停止し、接続済みMCUごとに新しい担当の`CONFIG` → 新担当がBot用ならそのBotの現在の正本FIFO使用量の`BUFFER`の順に送る。有効な`CONFIG`を受け取ったMCUが全出力を消灯して演出状態を初期化するため、直前の`CLEAR`は送らない。旧担当の`BUFFER`は復旧せず、旧役割の点灯を残さない。未割当になる接続済みMCUへは`CLEAR`だけを送り、以後の演出命令を停止する。

空きがない場合とPlaying中の初回接続では、管理画面へ公開して未割当で待機させる。切断だけでは割当を解除せず、再接続時は保持している対応を使用する。管理操作で未割当になったUIDは自動仮割当の対象から外し、旧基板が戻っても交換先の割当を奪い返させない。対応表と自動仮割当の対象外UIDはゲームのResetで維持する。サーバー再起動後の復元は初期実装の保証範囲に含めない。

## CONFIGの適用とゲームReset

MCUは`CONFIG`の引数をすべて検証し、NODEが担当リンク表にあるB1・B2・B3・P1・P3・P5・P7のいずれかであることを確認してから、一括で適用する。有効な場合は、旧担当で使用していた出力を含む全出力を消灯し、実行中の経路演出・尾・混雑度の表示状態を消去して新しいノード設定へ切り替える。同じNODEへの再設定、および実機確認用の一時設定でも毎回同じ初期化を行う。

Bot用へ設定した場合も、シグナルタワーは次の`BUFFER`を受け取るまで消灯を保持する。MCUが独自に`BUFFER 0`相当の青表示を開始しない。UIDとシリアル接続は維持し、`CONFIG`への応答として`HELLO`を送らない。不正な`CONFIG`では設定・表示・実行中の演出を変更せず、部分的に反映しない。

ゲームのResetでは、サーバーが全LEDの確認表示の周期送信を停止し、接続・識別・割当済みのLED制御MCUへ以下を送る。

| 担当 | Reset時の送信 |
|---|---|
| LED制御P1・P3・P5・P7 | `CLEAR` |
| LED制御B1・B2・B3 | `CLEAR` → `BUFFER 0` |

`BUFFER 0`はゲーム状態の初期化後に送信し、空き状態の青表示へ戻す。UIDの割当、MCUのノード設定、およびシリアル接続は維持し、`CONFIG`は再送しない。経路演出と尾は消去し、過去の`LIGHT`を再現しない。未割当で確認表示中の基板へは`CLEAR`だけを送り、以後の演出命令を停止する。確認終了時の復旧はこのReset手順に統合し、`CLEAR`・`BUFFER`を重複送信しない。未接続の機器へは送信せず、再接続時に通常の設定手順で初期化後の状態を通知する。

## 実機の確認表示

Preparing・Finishedで接続・識別済みのUIDを管理画面から選択し、既存の`CLEAR`・`LIGHT`・`BUFFER`を組み合わせて確認表示を行う。全IDが使用中でも、未割当の予備基板を対象にできる。プレイヤーMCUを含めサーバー全体で同時に1台だけを対象とする。確認専用のMCU命令は追加せず、周期送信はサーバーが行う。

確認用ノードIDは、割当済みなら現在の担当、未割当ならLED制御P1とする。開始時は確認用ノードIDの`CONFIG`を送り、MCUの表示・演出状態を初期化してから下記の周期送信を始める。未割当への`CONFIG`は一時的な表示用設定とし、P1が使用中でも正式な対応表・既存P1の担当・ゲーム状態を変更しない。未割当のまま確認表示を行い、一時設定を通常の演出通知の送信先として扱わない。

現在の`CONFIG`に対応する担当リンク表からGPIO0・1の出力を選ぶ。仮割当と現実の配置が異なっていても、この2出力にはLEDテープが接続されていることを前提とする。`LIGHT`のNEIGHBORには点灯するGPIOに対応する隣接ノードを、DESTINATIONには現在の割当先の論理ノードを指定し、DIRECTIONは`outgoing`とする。

開始時を0msとして、以下を1秒周期で繰り返す。命令は記載順に送信する。

| 周期内の時刻 | LED制御P1・P3・P5・P7 | LED制御B1・B2・B3 |
|---|---|---|
| 0ms | `CLEAR` → GPIO0に対応する`LIGHT` → GPIO1に対応する`LIGHT` | `CLEAR` → `BUFFER 4`でGPIO0のシグナルタワーを赤く点灯 → GPIO1に対応する`LIGHT` |
| 500ms | `CLEAR`で消灯 | `CLEAR`で消灯 |

GPIO0・1への`LIGHT`は通常の経路演出として再生する。`BUFFER 4`は確認表示だけの値とし、サーバーの正本FIFO件数を変更しない。Tickが遅延した場合、過去の周期をまとめて送らず、現在の周期内の表示だけを反映する。

確認を終了するときは周期送信を停止して`CLEAR`を送る。正式にBot用へ割当済みで担当が変わらない場合だけ、続けてそのBotの現在の正本FIFO使用量の`BUFFER`を送り、シグナルタワーを通常表示へ戻す。ゲームのResetに伴う復旧では初期化後の件数0を使用する。過去の`LIGHT`は再現しない。

担当変更・交換・付け替えによる終了では、上記の通常設定手順を用いて旧担当の`BUFFER`復旧を省く。未割当基板への正式な割当時も確認表示を終了して正式な`CONFIG`へ置き換える。未割当のまま確認を終了する場合と解除によって未割当になる場合は`CLEAR`だけを送り、以後の演出命令を停止する。一時的な`CONFIG`を正式な担当として使用せず、次の設定時に上書きする。

対象の切替、割当変更、ゲーム開始・Reset、HELLO再受信、切断時には[サーバー仕様](./server.md#422-実機の確認表示)に従って終了する。確認表示の開始・停止では自動仮割当の対象外UID情報を変更しない。切断時は送信せず、再接続後も確認表示を自動再開しない。

## メッセージ一覧

### LEDノード → Server

- HELLO:
  - UID

### Server → LEDノード

- identify: 共通のJSON形式で識別を要求し、`HELLO UID`での応答を求める

- CONFIG: ノード設定と表示・演出状態の初期化
  - NODE

- LIGHT:
  - NEIGHBOR
  - DESTINATION
  - DIRECTION (incoming|outgoing)

- BUFFER: (ボットノードのみで有効)
  - COUNT

- CLEAR: 全出力の表示を消去し、実行中の経路演出と尾を取り消す。シグナルタワーも消灯し、次の`BUFFER`まで消灯を保持する。後続の`LIGHT`・`BUFFER`は通常どおり受け付ける
