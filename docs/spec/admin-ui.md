# Web管理画面

> 状態: 承認済み（2026-10-28）。`static/`はこの設計に従って実装する。決めたことと未決の項目（配置図の向き）は14節にまとめる。

## 1. 対象と前提

[Web管理API仕様](./web.md)と[サーバー仕様](./server.md)で「別途定義」とした、管理画面のレイアウト、表示、操作手順、文言を定義する。APIの形式、操作の受理条件、取得と再試行の規則は各仕様に従い、本仕様で変更しない。

| 項目 | 前提 |
|---|---|
| 利用者 | 展示の運営スタッフ1〜2名。ノートPCの画面と設置物（直径約3mの環状配置）を見比べながら操作する |
| 接続 | サーバー機と同じLAN。認証なし。インターネットには接続していない場合がある |
| 画面 | ノートPCの横長画面。最小は1366×768とし、全画面表示（F11）で全体が1画面に収まるようにする。ブラウザーの枠を含めて高さが640px程度になる場合は、各欄の中だけスクロールする |
| 実装 | `server/internal/web/static/`の素のHTML・CSS・JS。ビルド工程と外部ライブラリを使わず、`go:embed`で同梱する。Webフォントも読み込まない |

通信の制御は実装済みの部品を使う。

| 部品 | 役割 |
|---|---|
| `api.js` | 5秒のタイムアウト。結果を`success`・`error`・`unknown`に分類 |
| `poller.js` | 500ms間隔の取得と失敗時の1秒間隔の再試行。古い応答の破棄 |
| `main.js`の`runCommand` | 管理操作を同時1件に限り、自動再送しない。操作後の再取得が済むまで、`<fieldset id="operations">`の`disabled`で全操作を無効にする |
| `view.js`の`setText` | 値が変わったときだけ`textContent`を書き換える |

## 2. 設計の方針

1. 部品の位置はフェーズで動かさない。フェーズによって変わるのは、強調と、押せるかどうかだけとする。続けてクリックしたときに、別の操作を押してしまうことを防ぐ。
2. ノードの表示色（7.1節）は、ノードを表す色札だけに使う。状態は文字と記号（●、×、!、✓、?、◎）で示し、色は補助にとどめる。
3. 実機と同じものを画面にも出す。表示名と色、環状の配置、確認表示の1秒周期の点滅を、画面でも同じ形で示す。
4. 操作の結果は、状態帯の決まった位置に出す。行ごとに別の場所へは出さない。
5. 押せるかどうかを画面が事前に判定するのは、開始可否（`canStart`）とフェーズ（8.3節）だけとする。操作の出し分けとセレクトの候補には、操作の意味を決める機器種別と割当の有無だけを使う（5.7節）。それ以外の受理条件は`app`の拒否で知らせる。画面独自のルールは足さない。

## 3. 利用場面

### 3.1. 設営時

| 項目 | 内容 |
|---|---|
| すること | 機器をつなぎ、台数と接続を確かめる。1台ずつ確認表示して実機の場所を特定し、正しい割当先に変えるか、別の機器と割当を入れ替える。故障した基板は予備と交代させる。終わったら確認表示を止める |
| 見る情報 | 機器欄の見出しの台数（接続数、割当先の埋まり具合）。切断と未割当の行。配置図の破線と×。確認表示帯 |
| 押す操作 | 機器の選択、確認表示を始める・止める、割当を変える、入れ替える、交代する、割当を外す、停止 |

仮割当では、基板が接続順に空き番号へ割り当てられる。そのため設営時の主な操作は、確認表示で実機の場所を特定したあとの「入れ替え」になる。手順は8.1節に示す。

### 3.2. 開始前

| 項目 | 内容 |
|---|---|
| すること | 手動で遊ぶプレイヤーを「手動」にする。プレイヤーが両端ボタンの長押しで準備完了したら、「開始」を押す。必要ならBotの処理速度を設定する |
| 見る情報 | コマンドバーの開始可否と、開始できない理由。プレイヤー表の準備列（! 未準備）と機器列（切断中は手動にできない） |
| 押す操作 | 手動・自動の切替、Botの処理速度の設定、開始 |

### 3.3. ゲーム中

| 項目 | 内容 |
|---|---|
| すること | 進行を見守る。必要ならBotの処理速度を変える。途中で止める場合は終了する |
| 見る情報 | 残り秒数、スコア、プレイヤーとBotのFIFO、Botの処理速度、機器の切断 |
| 押す操作 | Botの処理速度の設定、終了、（中止する場合の）リセット |

### 3.4. 終了後

| 項目 | 内容 |
|---|---|
| すること | 結果を確かめて記録する。次のゲームのためにリセットする。必要なら次のゲームに向けて手動・自動や割当を直す |
| 見る情報 | 最終スコア、順位（Snapshotへの追加が前提。14節）、ランキング対象外 |
| 押す操作 | リセット。手動・自動の切替と割当の操作も可 |

### 3.5. 異常時

| 事象 | 画面の表示 | 管理者がすること |
|---|---|---|
| 通信途絶 | 状態帯が赤くなり、最後に取得した時刻を示す。各欄は前回値のまま薄く表示し、枠を破線にする。操作はすべて無効になる | 待つ。画面は1秒ごとに自動で再取得する |
| 結果不明 | 状態帯の結果欄に「?」付きで、何の結果が不明かと理由を出す。次の操作まで残す | 再取得した値で反映されたかを確かめ、必要なら手で操作し直す。入れ替えの再送は割当を元に戻し、リセットの再送はもう一度初期化する |
| 機器の切断 | 機器欄の見出しに「割当済みの機器がn台切断しています」。該当行を赤い地にし、「× 切断」と書く。プレイヤー表の機器列、配置図の×にも出す | 切断したプレイヤーは`app`が自動操作に切り替える。ゲーム中ならランキング対象外になる。再接続しても手動には戻らないので、準備中か終了後に、必要なら手動へ戻す |

## 4. 画面構成

### 4.1. 配置

1366×768での配置を次に示す。図の`[A]`などは色札、`(A)`は配置図の円、`[I]`は配置図のBotを表す。

```text
+-------------------------------------------------------------------------------------------+
| D4 Exhi 管理画面   接続状態   操作の結果（1件）                  処理中                   |  状態帯 48px
+----------------+------------------+-----------------------------------------+-------------+
| 準備中         | 残り時間         | 開始可否                                |             |  コマンドバー
| (30px 太字)    | 120 秒 / 120 秒  | 開始できない理由    +----------+        | [ 終了 ]    |  90px
|                | (50px 太字)      | - 未準備 [B] [E]    |   開始   |        |             |
| 準備中>ゲーム中| [==========]     |                     +----------+        | [リセット]  |
+-------------------------------+-----------------------------+-----------------------------+
| プレイヤー表（8 行）          | 機器                        | 配置図                      |
| ノード 機器 操作 準備         | [確認表示帯        ][停止]  |    (A)  (B)                 |
|   FIFO スコア 順位            | 選択 Device ID 接続 割当    |  (H)   [I]   (C)            |
| [A] P1 接続 [手動|自動] ...   | > プレイヤー基板 割当先 8/8 |  (G) [K]  [J] (D)           |
|   ...                         |   ( ) 0C8B95A1F2D4 ...      |    (F)  (E)                 |
+-------------------------------+                             +-----------------------------+
| Bot 表（3 行）                |   ...                       | 選択中の機器（操作パネル）  |
| [I] B1 FIFO 1/4 1 pps         | > LED制御基板 割当先 7/7    | 48E729A0B1C4 [選択を解除]   |
|   [    ] pps [設定]           |   ( ) 10521CF0A1B2 ...      | [確認表示を始める]          |
|                               |   ...                       | [空き割当先 v][割当を変える]|
+-------------------------------+-----------------------------+-----------------------------+
  左列 約495px                   中列 約430px                  右列 約365px
```

| 領域 | 大きさ | 内容 |
|---|---|---|
| 状態帯 | 高さ48px。結果欄の2行分を常に確保する（10節） | 画面名、接続状態、操作の結果、処理中 |
| コマンドバー | 高さ90px。列幅196px・268px・残り・132px | フェーズ、残り時間、開始可否と開始、終了とリセット |
| 左列 | `minmax(470px, 1.36fr)` | プレイヤー表（8行）、Bot表（3行） |
| 中列 | `minmax(410px, 1.18fr)` | 機器一覧と確認表示帯 |
| 右列 | `minmax(330px, 1fr)` | 配置図、選択中の機器（操作パネル） |

状態帯は`<fieldset id="operations">`の外に置き、操作部品を持たない。コマンドバー以下はすべて`<fieldset id="operations">`の中に置く。

1366×768では、プレイヤー表、Bot表、機器一覧（通常構成の15台と予備1台）、操作パネルが、どれもスクロールせずに収まる。高さが足りないときは、機器一覧と操作パネルが欄の中でスクロールし、状態帯とコマンドバーは常に見える。幅が1200px未満のときは、右列を左列・中列の下へ回す。960px未満では1列に並べ、ページ全体をスクロールする。この2つは最小想定より狭い場合の逃げ道とし、操作の手順は変えない。

### 4.2. 何を目立たせるか

| 優先 | 要素 | 扱い |
|---|---|---|
| 1 | フェーズ | コマンドバー左端に30pxの太字で出す。下に「準備中›ゲーム中›終了」の順序を示し、現在のフェーズを太字にする |
| 1 | 残り秒数 | 50pxの太字の等幅数字で出す。ゲーム中は濃く、準備中と終了は薄くする。下に残りの割合を細い棒で示す |
| 1 | 開始と開始できない理由 | 開始ボタンを高さ64pxの最も大きい部品にする。押せるときは黒地に白文字。左に開始可否と理由を並べる |
| 2 | フェーズごとの主な列 | プレイヤー表で、準備中は「準備」、ゲーム中は「スコア」、終了は「順位」の列見出しを太字にする |
| 2 | 切断と未割当 | 機器欄の見出しと該当行で示す |
| 3 | それ以外 | 標準の大きさと色で示す |

## 5. 各領域

### 5.1. 状態帯

| 要素 | 表示 |
|---|---|
| 画面名 | 「D4 Exhi 管理画面」 |
| 接続状態 | 接続中: 「● 接続中」。正常: 「● 正常」と「最終取得 HH:MM:SS」。通信途絶: 帯全体を赤い地にし、「× 通信途絶」と「HH:MM:SS の値を表示中。再接続しています」を出す。一度も取得できていない場合は「まだ取得できていません。再接続しています」とする |
| 結果欄 | 10節の表現で、最後の操作の結果を出す。次の操作を送るまで残す。結果がなければ空白にし、場所は確保しておく。長い結果は欄の幅で折り返す |
| 処理中 | 操作を送ってから、再取得が済むまで「処理中…」を出す |

接続状態と結果欄は`role="status"`とし、変わったときだけ読み上げられるように`setText`で書く。最終取得の時刻は読み上げ対象に含めない。

### 5.2. コマンドバー

| 要素 | 表示・操作 |
|---|---|
| フェーズ | 7.4節の語。表にない値はそのまま表示する |
| 残り時間 | `remainingSeconds`をそのまま「87 秒」と表示し、「/ 120 秒」を添える。画面側でカウントダウンしない |
| 開始可否 | `canStart`がtrueなら「✓ 開始できます」、falseなら「開始できない理由」と、`startBlockers`の文言（11.2節）を並べる。`players_not_ready`の対象は色札と「B（P2）」の形で並べる |
| 開始可否の補足 | `canStart`がtrueで、manualのプレイヤーがいない場合は「手動のプレイヤーがいないため、全員自動で始まります」と添える。終了中は「次のゲームは、リセットして準備中に戻してから始めます」と添える |
| 開始 | `canStart`がtrueのときだけ押せる（web.md 3.3）。確認ダイアログは出さない |
| 終了… | ゲーム中だけ押せる。確認ダイアログを出す |
| リセット… | 常に押せる。確認ダイアログを出す |

開始・終了・リセットの位置はフェーズで変えない。理由が`not_preparing`だけの場合は、開始できないのが通常の状態なので、見出しを赤にせず灰色で示す。`pid_exhausted`はゲーム中でも赤で示し、次のゲームの前にサーバーの再起動が必要なことを早めに伝える。

### 5.3. プレイヤー表

P1〜P8を常にこの順で8行に並べる。スコア順に並べ替えない。実機の配置と照合するときに、行の位置を固定しておくためである。

| 列 | 表示 |
|---|---|
| ノード | 色札、表示名、ノードID（例: 色札 A、「A」「P1」） |
| 機器 | そのプレイヤー割当先の機器の接続。「● 接続」「× 切断」「— なし」 |
| 操作 | 「手動」「自動」の2つのボタン。現在のモードを押下状態（`aria-pressed="true"`）で示す。押下されていない方を押すと切り替える。押下されている方を押しても要求は送らない |
| 準備 | manualだけ「✓ 準備完了」「! 未準備」。autoは「—」。準備中以外は薄い文字にして、強調しない |
| FIFO | `fifoLength`の数 |
| スコア | `score`の数。ゲーム中と終了は太字にする |
| ランキング | 準備中（`rankingEligible`がnull）は「—」。ゲーム中は「対象」または「対象外」（警告色）。終了は「1 位」の形の順位（Snapshotへの追加が前提。14節）または「対象外」 |

見出しの横に、準備中は「手動 7 人、うち準備完了 5 人」、終了は「手動 n 人」、ゲーム中は「ゲーム中は操作モードを変更できません」と出す。

### 5.4. Bot表

B1〜B3を3行で並べる。

| 列 | 表示・操作 |
|---|---|
| ノード | 色札、表示名、ノードID |
| FIFO | 4マスのメーターと「n / 4」 |
| 処理速度 | `ratePps`を「1.5 pps」の形で表示 |
| 変更 | 数値の入力欄、「pps」、「設定」ボタン。入力欄はポーリングで書き換えず、現在値も入れない。空欄のまま押すか、数として読めない場合は、要求を送らずに入力欄の横に「処理速度を数で入力してください」と出す。0以下の数は送り、`app`の拒否を11.4節の文言で示す。成功したら入力欄を空にする。入力欄でEnterを押すと、その行の「設定」と同じ動作をする |

見出しの横に「処理速度は全フェーズで変更できます」と出す。

### 5.5. 機器一覧

`devices`を機器種別ごとに「プレイヤー基板」「LED制御基板」の2群に分け、各群ではAPIの順（Device ID順）に並べる。割当を変えても行の位置は動かない。

予備基板や交代後の旧基板も一覧に含まれるので、基板の台数はノードの数（プレイヤー8、Bot3）や割当先の数（LED制御7）を超えることがある（web.md 3.2）。基板の総数を見出しに出すと、プレイヤーやBotの数と取り違えやすい。そのため見出しには総数を出さず、割当先の数と未割当の台数を分けて出す。

| 要素 | 表示 |
|---|---|
| 見出しの補足 | 割当済みの切断機器があれば「割当済みの機器が n 台切断しています」（警告色）。なければ「割当先 n / 15 が接続済み」とし、15に満たなければ警告色にする。15はプレイヤー8とLED制御7の割当先の数 |
| 確認表示帯 | 一覧の上に常に置く。確認表示中は「◎ 確認表示中」、Device ID、表示内容（7.3節）、「停止」ボタン。確認表示がなければ「確認表示: なし」と、次にすることの案内（ゲーム中は「ゲーム中は確認表示を始められません」） |
| 群の見出し行 | 割当先の埋まり具合を先に出し、割当先を超える分は「未割当」として分けて書く。例: 「プレイヤー基板　割当先 8 / 8（うち切断 1）　未割当 1 台」「LED制御基板　割当先 6 / 7　未割当 1 台（うち切断 1）」。割当先の分母は、プレイヤーが8、LED制御が7。切断と未割当が0のときは、その部分を書かない |
| 選択 | ラジオボタン。行のどこを押しても選択する |
| Device ID | 等幅の書体（7.2節） |
| 接続 | 「● 接続」または「× 切断」 |
| 割当 | 割当があれば色札と「A（P1）」または「LED P1」。なければ破線の空札と「未割当」 |
| 確認表示 | 確認対象の行だけ表示する（7.3節） |

機器の状態の見分け方は7.3節に示す。

### 5.6. 配置図

設置物を上から見た図として、プレイヤー8ノードを外周、Bot3ノードを内側に置き、ルート24本を線で結ぶ。表示専用とし、操作部品を置かない。

|---|---|
| 円（色札の色、表示名入り） | プレイヤー割当先。塗りは割当済み、破線の輪は機器なし、薄い塗りに×は切断 |

| 橙の破線の輪と1秒周期の点滅 | 確認表示中の機器の割当先。未割当の機器の一時表示は、その機器がその位置にあるわけではないので、図に出さない |

### 5.7. 選択中の機器（操作パネル）

機器一覧で選んだ1台の詳細と、その機器への操作を出す。選択はDevice IDで保持し、ポーリングで外れない。

| 状態 | 表示 |
|---|---|
| 未選択 | 「機器の一覧から 1 台選ぶと、確認表示と割当の操作がここに出ます。」 |
| 選択中 | Device ID（大きく）、「選択を解除」、種別、接続、割当。確認表示中は、その内容を橙の地で示す（例: 「確認表示中: 実機は一時的に A（P1）を点滅表示しています。割当ではありません。」） |
| 選択した機器が一覧から消えた | 選択を外し、「選択していた機器 XXXX は一覧にありません」と出す |

操作は、選択した機器が割当済みか未割当かで出し分ける。セレクトの最初の選択肢が「何を選ぶか」を表すので、見出しは画面に出さず、`aria-label`に持たせる。

| 選択中の機器 | 部品（上から） |
|---|---|
| 割当済み | 「確認表示を始める」（確認表示中は「確認表示を止める」）、「割当を外す」／［空いている割当先を選ぶ］「割当を変える」／［入れ替える相手を選ぶ］「入れ替える…」／［交代する相手を選ぶ］「交代する…」／説明「入れ替え: 2 台の割当先を取り替える。交代: 割当を相手に渡し、この機器は未割当になる。」 |
| 未割当 | 「確認表示を始める」（確認表示中は「確認表示を止める」）／［空いている割当先を選ぶ］「割り当てる」／［交代する相手を選ぶ］「交代する…」／説明「交代: 相手の割当をこの機器が引き継ぎ、相手は未割当になる。故障した機器を予備に替えるときに使う。」 |

ボタンには、押すと何が起きるかを表す動詞を書く（7.4節）。「入れ替える」と「交代する」は、どちらも2台を選ぶので取り違えやすい。そのため、違いを1行の説明でパネルの下に常に出す。説明は12pxで2行以内に収める。

各セレクトの候補は次のとおりとする。候補は機器種別と、操作の意味に必要な割当の有無（入れ替える相手と、未割当の機器から選ぶ交代の相手は割当済み）で絞り込む。接続や使用中の状態は候補の文に書き添えるだけで、除外しない。受理するかどうかは`app`が判定する。

| セレクト | 候補と並び | 候補の文の例 |
|---|---|---|
| 空いている割当先 | 同じ種別の割当先すべて。プレイヤーはP1〜P8、LEDはB1・B2・B3・P1・P3・P5・P7の順 | 「C（P3） 空き」「C（P3） 使用中 0C8B95A1F2D4」「B（P2）（現在の割当）」 |
| 入れ替える相手 | 同じ種別で割当済みのほかの機器。割当先の順 | 「C（P3）  0C8B95A1F2D4」「F（P6）  A0B765F0C3E2（切断中）」 |
| 交代する相手（割当済みを選択中） | 同じ種別のほかの機器すべて。未割当で接続中の機器を先に、Device ID順 | 「48E729A0B1C4  未割当」「E89F6D1C2B3A（切断中）  現在 LED P5」 |
| 交代する相手（未割当を選択中） | 同じ種別で割当済みのほかの機器。割当先の順 | 「F（P6）  A0B765F0C3E2（切断中）」 |

### 5.8. 確認ダイアログ

`<dialog>`要素を1つだけ`<fieldset id="operations">`の中に置き、`showModal()`で開く。開いている間に通信途絶や処理中になると、確定ボタンもfieldsetの`disabled`で押せなくなる。

- 確認ダイアログを出すのは、終了、リセット、入れ替え、交代の4つとする。割当を外す操作には出さない。誤って外しても割り当て直せば戻せる（プレイヤーは自動操作になる）うえ、機器を選んでから押す手順なので、誤って押しにくいためである。
- 初期フォーカスは「キャンセル」に置く。Escと「キャンセル」は何も送らずに閉じ、開く前に押したボタンへフォーカスを戻す。
- 送る内容（type・data、対象のDevice ID）は開いた時点で決め、開いている間は変えない。本文の値（残り秒数、現在の割当）は、ポーリングで取得した値に`setText`で合わせる。
- 確定ボタンの名前は操作の名前と同じにする（「入れ替える」「ゲームを終了する」）。終了とリセットの確定ボタンは赤地にする。
- 文言は11.6節に示す。

割当の操作は、画面では押すと何が起きるかが分かる動詞で呼ぶ。サーバー仕様の名前との対応は次のとおり。

| 画面の名前 | 起きること | サーバー仕様の名前 | type |
|---|---|---|---|
| 割り当てる | 未割当の機器を、空いている割当先に割り当てる | 割当（SetDeviceAssignment） | `set_device_assignment` |
| 割当を変える | 割当済みの機器を、空いている別の割当先に変える | 移動（SetDeviceAssignment） | `set_device_assignment` |

## 8. 操作の流れと押せない操作の見せ方

### 8.1. 2台を選ぶ操作

入れ替えと交代は、1台目を機器一覧で選び、2台目を操作パネルのセレクトで選ぶ。

1. 機器一覧で1台目の行を押す。操作パネルにその機器の操作が出る。
2. 操作パネルのセレクトで2台目を選ぶ。候補には割当先と接続が書いてあるので、入れ替える相手は「どの割当先の機器と入れ替えるか」で選べる。
3. 「入れ替える…」または「交代する…」を押す。確認ダイアログに2台の今の割当と操作後の割当を表で出す。
4. ダイアログで「入れ替える」「交代する」を押すと送る。

取り消しは、どの段階でもできる。

| 段階 | 取り消し方 |
|---|---|
| 1台目を選んだあと | 「選択を解除」を押すか、一覧で別の行を選ぶ。別の行を選ぶと、操作パネルのセレクトはすべて最初の選択肢に戻る |
| 2台目を選んだあと | セレクトを最初の選択肢に戻す。ボタンを押さなければ何も送らない |
| ダイアログ | 「キャンセル」かEscで閉じる。何も送らない |

設営時の典型的な流れは次のとおり。

1. 機器一覧で24D7EB10A9C0（今はB（P2））を選び、「確認表示を始める」を押す。
2. 実機を見ると、Cの位置にある基板がBを点滅表示している。
3. 「入れ替える相手を選ぶ」のセレクトで「C（P3）  0C8B95A1F2D4」を選び、「入れ替える…」を押す。
4. ダイアログで、24D7EB10A9C0がB→C、0C8B95A1F2D4がC→Bになることを確かめ、「入れ替える」を押す。入れ替えで確認表示は自動で終わる。

### 8.2. 予備との交代

故障した基板が割当済みのまま切断している場合は、次のどちらの向きでも交代できる。送る要求は同じである。

- 故障した基板（赤い行）を選び、「交代する相手を選ぶ」で予備を選んで「交代する…」を押す。
- 予備（未割当の行）を選び、「交代する相手を選ぶ」で故障した基板を選んで「交代する…」を押す。

どちらの向きでも、割当は故障した基板から予備へ移り、故障した基板が未割当になる。向きは、選んだ機器が割当済みか未割当かで決まる（6節）。

### 8.3. フェーズで受理されない操作

[サーバー仕様4.2](./server.md#42-管理クライアントからの入力)の受理フェーズに合わせて、画面でも部品を`disabled`にする。フェーズ以外の受理条件（接続、割当の競合、manualの確認表示、準備完了、PID）は事前に判定せず、`app`の拒否を11.4節の文言で示す。表示中のSnapshotが古い場合もあるため、最終的な判定は`app`に任せる。

| 操作 | 準備中 | ゲーム中 | 終了 |
|---|---|---|---|
| 開始 | `canStart`に従う | `canStart`に従う | `canStart`に従う |
| 終了 | 押せない | 押せる | 押せない |
| リセット | 押せる | 押せる | 押せる |
| 手動・自動 | 押せる | 押せない | 押せる |
| Botの処理速度 | 押せる | 押せる | 押せる |
| 確認表示を始める | 押せる | 押せない | 押せる |
| 確認表示を止める・停止 | 押せる | 押せる | 押せる |
| 割り当てる・割当を変える・割当を外す・入れ替える・交代する | 押せる | 押せない | 押せる |

押せない部品は灰色で表示し、隠さない。理由は部品ごとのツールチップではなく、欄の見出しの横に1行で出す（例: プレイヤー表「ゲーム中は操作モードを変更できません」、操作パネル「ゲーム中は割当を変更できません」）。`phase`が3つのどれでもない場合は、フェーズによる無効化を行わず、`app`の判定に任せる。

fieldsetの`disabled`（初回取得前、通信途絶、処理中）は、これとは別に全部品へかかる。

## 10. 結果の表示

操作の結果は状態帯の結果欄に1件だけ出し、次の操作を送るまで残す。文の先頭に記号を付け、色だけに頼らない。

長い結果は、結果欄の幅（1366pxで全角約55〜65字。通信途絶の表示中は狭くなる）で折り返す。欄の外へはみ出させず、末尾を「…」で省略もしない。状態帯は結果欄の2行分の高さ（48px）を常に確保する。こうしておけば、長い結果が出てもその下の部品の位置が動かない。11節の文言は、1366pxでは最も長いもの（Device IDを2つ含む拒否や結果不明）でも2行に収まる。1366pxより狭い画面で3行以上になる場合だけ、状態帯を伸ばす。

| 結果 | 判定（`api.js`の結果） | 表現 |
|---|---|---|
| 処理中 | 送信から再取得の完了まで | 灰色の地。「C（P3）を手動にしています…」 |
| 成功 | `success` | 緑の文字と地。「✓ C（P3）を手動にしました」 |
| 拒否 | `error`で、HTTPステータスが500・503以外 | 赤の文字と地。「× C（P3）を手動にできませんでした: 対応する機器が接続されていません（device_disconnected）」 |
| 結果不明 | `unknown`、または`error`で500・503、または`runCommand`内の例外 | 橙の文字と地、太字。「? 「ゲームの終了」の結果は不明です（タイムアウト）。再送はしません。状態を確かめてください」 |

拒否の文言は`code`だけで選ぶ。`message`の文面では分岐せず、表示もしない。`details.nodeIds`のように仕様で定めた追加情報は文言に使う。`code`を括弧で添えるのは、問い合わせのときに伝えやすくするためである。

### 11.6. 確認ダイアログ

## 12. 実装上の制約

| 制約 | 実現方法 |
|---|---|
| 操作部品はすべて`<fieldset id="operations">`の中 | コマンドバー、3列の各欄、`<dialog>`をfieldsetの中に置く。状態帯は操作部品を持たないので外に置く。配置図は操作部品を持たない |
| 操作は必ず`runCommand()`を通す | クリックは`actions.js`でコマンドに変換し、`runCommand(command, phrases)`だけを呼ぶ。`fetch`を直接呼ばない |
| 500msごとの再描画で、開いているセレクトや入力中の値を失わない | 下の「差分更新」に従う |
| 外部由来の値は`textContent`で表示 | Device ID、ノードID、`code`、`details`の値、`<option>`の文、SVGの`<text>`も含め、`textContent`と属性だけで埋める。`innerHTML`は使わない |
| 色だけに頼らない | 色札には表示名を必ず書き、隣に「A」「P1」も文字で出す。状態は「● 接続」「× 切断」「! 未準備」「未割当」などの文字で書く。点滅には文字の「確認表示中」を必ず伴わせる |

差分更新の規則は次のとおり。

- プレイヤー表の8行とBot表の3行は、最初のSnapshotで1度だけ作り、以後はノードIDをキーにセルを`setText`と属性で更新する。
- Botの入力欄は、ポーリングで値を書き換えない。
- 機器一覧の行はDevice IDをキーに持つ。増えた機器は並び順の位置に挿入し、消えた機器の行は外す。既存の行はセルだけを更新し、作り直さない。
- 操作パネルは、選択中の機器が変わったときに作り直す。同じ機器の値が変わったときは`setText`で更新する。
- セレクトの候補は、候補の一覧（値と文）が変わったときだけ作り直し、選んでいた値が残っていれば選び直す。セレクトにフォーカスがある間は作り直さず、`blur`で反映する。
- 配置図のSVGは最初に骨格を作り、以後は`class`と属性だけを更新する。
- ダイアログの本文は`setText`で更新し、送る内容は開いた時点のまま変えない。
- 確認表示の点滅の`class`は、確認対象が変わったときだけ付け外しする（7.3節）。

アクセシビリティとして、次を満たす。

- 色札は`aria-hidden="true"`とし、表示名は隣の文字で読ませる。
- ボタンの`aria-label`には対象を含める（「C（P3）を手動にする」）。
- 機器のラジオボタンは同じ`name`の1群にし、矢印キーで選択を移せるようにする。
- フォーカスの枠は2pxの実線で常に見えるようにする。

## 14. 決定事項と未決事項

2026-10-28に次を決めた。

| 項目 | 選んだもの | 退けたもの | 理由 |
|---|---|---|---|
| 機器一覧の形 | 表＋選択中の機器パネル | 1台1枚のカード（操作ボタンをカードに置く） | 予備を含む16台を1画面に並べられ、行の位置が動かないため |
